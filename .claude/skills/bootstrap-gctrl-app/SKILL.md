---
name: bootstrap-gctrl-app
description: Bootstrap a new gctrl native application — thin wrapper around `gctrl app bootstrap <name>`. Scaffolds <app-dir>/ with PRD.md, WORKFLOW.md, ROADMAP.md, vault/ stub at the gctrl repo's apps/<name>/ by default, or anywhere on disk via --target (external repo, sibling project, etc.). The PRD is generated by the kernel LLM relay (default model claude-opus-4-7) so it follows the project's prd-template.md and matches existing apps. Usage - /bootstrap-gctrl-app <name> [<one-line description>] [--target <path>] [--gctrl-root <path>] (e.g. /bootstrap-gctrl-app gctrl-watch "Watchtower for agent runs", or /bootstrap-gctrl-app my-app "..." --target ~/code/other-repo/apps/my-app).
---

The actual scaffolding logic lives in the gctrl shell command `gctrl app bootstrap` (`shell/gctrl-shell/src/commands/app.ts`). This skill is a thin coordinator: it parses the user's input, sanity-checks the environment, runs the command, and reports.

Do NOT reimplement the LLM call, template loading, or file writing here — if you find yourself wanting to, the change belongs in the gctrl shell command instead.

## Inputs

- `<name>` (required) — kebab-case app slug, e.g. `gctrl-watch`.
- `<one-line description>` (optional) — short pitch passed via `--description`.
- `--target <path>` (optional) — bootstrap into an arbitrary directory instead of `apps/<name>/`. Use this when the app lives in another repo or a non-default location.
- `--gctrl-root <path>` (optional) — path to a gctrl repo checkout, used to resolve the PRD template + example. Required when `--target` points outside a gctrl checkout and the current working directory isn't one either.

If `<name>` is missing, ask the user once before proceeding. If the description is missing, run with the gctrl command's built-in default — don't badger the user.

## Two modes

**In-tree (default).** Run from the gctrl repo root; output goes to `apps/<name>/`. Both `<name>` and the gctrl repo's `apps/gctrl-board/vault/specs/workflows/` (template + example) are resolved from CWD.

**External project.** The app lives in another repo or non-default location. Pass `--target <abs-path>` for the output directory. Templates are resolved in this order: `--gctrl-root <path>` → `$GCTRL_REPO_ROOT` env → CWD. If none of those points to a gctrl checkout, the command bails with a clear error.

## Pre-flight

1. **Output location.**
   - In-tree: CWD must contain `apps/`. If not, either `cd` into the gctrl repo root or switch to external mode with `--target`.
   - External: `--target` must be an absolute path (or one resolvable from CWD). The parent directory should exist; the leaf directory must not exist (use `--force` to overwrite).
2. **Template resolution (external mode).** Confirm `--gctrl-root`, `$GCTRL_REPO_ROOT`, or CWD points to a gctrl checkout that contains `apps/gctrl-board/vault/specs/workflows/prd-template.md`. The current gctrl repo at `/Users/debuggingfuture/workspaces/ohc/gctrl` is a safe default to pass via `--gctrl-root` if the user doesn't specify one.
3. **Branch hygiene.** Create a feature branch *in the target repo* before running: `cd <target-repo> && git checkout -b feat/bootstrap-<name>`. Never run on `main`/`master`. For external targets, the branch belongs to the *external* repo, not the gctrl repo.
4. **Build the shell if missing.** If `~/.local/bin/gctrl` is absent or `gctrl --version` fails, run `cd <gctrl-checkout>/shell/gctrl-shell && pnpm run build` once.

## Procedure

### Step 1 — Run the command

`@effect/cli` requires **all flags before the positional `<name>`**. Putting `<name>` first will fail with `Received unknown argument: '--description'`.

In-tree:

```sh
gctrl app bootstrap --description "<description>" <name>
```

External (app in another repo):

```sh
gctrl app bootstrap \
  --description "<description>" \
  --target /abs/path/to/external-repo/apps/<name> \
  --gctrl-root /Users/debuggingfuture/workspaces/ohc/gctrl \
  <name>
```

Useful flags (pass through if the user requested them):
- `--target <path>` — full output directory for the new app (overrides `apps/<name>` default).
- `--gctrl-root <path>` — gctrl repo checkout for template/example resolution. Falls back to `$GCTRL_REPO_ROOT`, then CWD.
- `--model <id>` — override the LLM model (default `claude-opus-4-7`).
- `--llm-url <url>` — override the LLM endpoint (default `$GCTRL_LLM_URL` or `http://127.0.0.1:4319/v1/chat/completions`).
- `--dry-run` — preview without writing.
- `--force` — overwrite an existing target directory.

The command does its own pre-flight (kebab-case validation, target collision check, gctrl-root resolution, exemplar/template loading, kernel relay call) and exits non-zero with a clear message on failure. Surface the exit message to the user verbatim.

### Step 2 — Report

After a successful run, output (substitute `<app-dir>` with the resolved target path — `apps/<name>` for in-tree, or the `--target` value for external):

```
## Bootstrapped: <name>

**Branch**: feat/bootstrap-<name> (in <target-repo>)
**Files**:
- <app-dir>/PRD.md
- <app-dir>/WORKFLOW.md
- <app-dir>/ROADMAP.md
- <app-dir>/vault/{,specs/}.gitkeep

### Next steps
- Read through PRD.md and edit anything that drifted from intent
- Commit when ready (in the target repo): `git add <app-dir> && git commit -m "feat(<name>): bootstrap PRD + workflow"`
- Seed issues from the Roadmap: `gctrl board create --project <PROJ> ...`
```

Do NOT commit, push, or open a PR. Stop at "ready for review."

## Guardrails

- **No direct LLM calls from the skill.** All generation goes through `gctrl app bootstrap`, which routes via the kernel relay. The whole point of this design is that cost + spans land in the kernel.
- **No `cat <<EOF` heredocs.** The skill writes nothing to disk directly — the gctrl command owns file writes.
- **Bootstrap on a feature branch in the target repo**, never on `main`. For external targets, that's the external repo's main, not gctrl's.
- **If the user asks to change template wording, default model, or file layout**, edit `shell/gctrl-shell/src/commands/app.ts` (and add a test) — not this skill file.
- **External target must still be a gctrl-shaped app.** The output is always `<app-dir>/{PRD,WORKFLOW,ROADMAP}.md + vault/`. If the user wants a totally different layout, they don't want this skill.
